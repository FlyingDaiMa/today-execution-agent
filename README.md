# 今日执行 Agent

这是《今日执行 Agent》的 MVP 服务端项目。第一阶段目标是验证飞书机器人能够通过长连接接收个人私聊消息并自动回复。

## 本地配置

1. 安装 Python 3.11 或兼容版本。
2. 创建并启用虚拟环境。
3. 运行 `pip install -r requirements.txt` 安装依赖。
4. 将 `.env.example` 复制一份并命名为 `.env`。
5. 在 `.env` 内填写飞书和运行时模型配置。
6. 运行 `python main.py` 启动机器人。

7. 不要上传、分享或截图 `.env`。

### GitHub 安全边界

仓库只保存源码、测试、依赖清单、示例配置和项目说明。以下内容只保留在本地：

- `.env` 与任何真实密钥
- `today_execution.db` 等用户任务数据库
- 机器人运行日志
- `.venv`、缓存和临时文件
- 文档构建过程、验收图片和作品集交付文件

首次提交和后续推送前，运行 `python scripts/security_check.py`。脚本只报告
风险文件、行号和风险类型，不输出疑似密钥内容。

如果真实密钥曾经进入 Git 提交历史，即使之后删除文件，也应立即在飞书开放平台
或模型服务商处轮换密钥，不能只依赖删除 GitHub 文件。

## 主动推送设置

主动推送默认关闭，不会在未确认时间的情况下自动发送。
完成首次使用设置后，可在与机器人的飞书私聊中发送：

- `设置晨间计划 HH:MM`
- `设置晚间总结 HH:MM`
- `查看推送设置`
- `关闭晨间计划`
- `关闭晚间总结`

时间使用 24 小时制。设置具体时间会同时开启对应推送。

## Excel 课表导入

完成首次使用设置后，可在与机器人的飞书私聊中直接发送教务系统导出的
`.xlsx` 课表。机器人会：

1. 解析星期、节次、教学周、课程名称和地点。
2. 询问本学期第一周星期一的日期。
3. 展示导入数量和日期范围，等待用户确认。
4. 确认后写入固定安排，生成今日计划时自动避开课程。

重复导入同一学期会替换原课表记录，不影响手工添加的忙碌时间。
当前支持 `.xlsx` 和 UTF-8 编码的 `.ics` 文件，不支持旧版 `.xls`。

下载飞书消息中的课表附件需要同时开通以下应用身份权限：

- `im:resource`：获取与上传图片或文件资源
- `im:message:readonly`：获取单聊、群组消息

## AI 任务拆分与子任务进度

对已经创建且仍为待完成状态的任务，可在飞书私聊中发送：

- `拆分 #7`：生成 3—6 条 AI 执行步骤，确认后才保存
- `查看 #7 子任务`：查看步骤和整体完成百分比
- `#7-2 完成了`：勾选第 2 个子任务
- `恢复 #7-2`：将误勾选的子任务恢复为未完成

所有子任务完成后，机器人仍会询问是否确认完成主任务，不会擅自修改主任务状态。

## 任务风险提醒与补救计划

机器人会在 08:00—22:00 定期检查待完成任务。任务已逾期、剩余时间无法
容纳剩余工作量，或距离截止不足 24 小时且当前进度低于建议进度时，会主动
说明风险原因，并询问用户当前时间、状态和临时安排。

用户提供状态后，机器人会：

1. 优先保护临近截止的风险任务。
2. 保留课程、会议等固定安排。
3. 给出新的执行时段和建议暂缓的低优先级任务。
4. 等待用户回复 `确认调整` 或 `暂不调整`。

一分钟内没有确认时，原任务和原计划保持不变，机器人只提醒一次。同一任务
同一天不会重复发送风险提醒。确认后的方案可发送 `查看补救计划` 重新查看。

## 待安排池与可选任务

创建任务时，如果明确说明“没有截止日期”“无明确截止”“长期任务”或
“有空再做”，机器人不会继续追问截止日期，而是先展示确认页；确认后任务
进入待安排池。可以在飞书私聊中发送：

- `查看待安排池`
- `待安排池`
- `查看可选任务`

生成今日计划和晨间计划时，系统会先安排有截止日期的任务。待安排池任务只有
在当天剩余空闲能够完整容纳时才会标为“待安排池可选”，不会挤占课程、会议、
其他固定安排或更高优先级的截止型任务。空间不足时，任务会继续留在池中。

## 个性化事务优先级

任务会被识别为健康、家庭、学习、工作与兼职、个人生活或其他事务。用户可以
亲自设置六类事务从高到低的顺序：

- `设置事务优先级 家庭 > 健康 > 学习 > 工作与兼职 > 个人生活 > 其他`
- `查看事务优先级`

类别顺序用于调整其他条件相近的任务，但不会覆盖课程、明确不可移动安排或
临近截止风险。已有用户未设置时保持中立，不会由系统擅自代选。

## 每日计划快照、完成率与提醒

生成晨间计划或发送 `安排我的今天` 后，系统会同时保留当天稳定的统计基线和
最新动态排程。进度更新、任务完成或任务修改可以刷新后续执行时段，但不会覆盖
已经承诺的计划基线。晚间总结依据基线任务、任务完成状态和剩余工作量计算计划
完成率，不把课程计入任务完成率。

计划中的课程开始前约10分钟会提醒一次；任务最后一个计划时段结束后会询问是否
完成或还需要多少时间。提醒成功后写入幂等记录，同一提醒不会重复发送，普通提醒
仅在 08:00—22:00 发送。

任务进度既可以按剩余时间反馈，也可以按百分比反馈，例如：

- `#12还需要30分钟`
- `#12进度60%`

进度达到100%时仍需用户确认，系统不会直接把任务标记为完成。

## 晨间兴趣资讯彩蛋

资讯彩蛋默认关闭，只有用户亲自设置关键词后才启用：

- `设置兴趣关键词 AI产品，飞书`
- `查看兴趣资讯设置`
- `关闭资讯彩蛋`

晨间计划最多附带5条外部来源资讯，包含标题、来源、摘要和原文链接。链接无效的
条目不会展示；网络或资讯源失败时只跳过彩蛋，不影响正常晨间计划主动推送。

## 助手语气

用户可亲自选择进度鼓励和晚间总结的表达方式：

- `设置助手语气 温柔陪伴`
- `设置助手语气 活泼夸夸`
- `设置助手语气 简洁专业`
- `查看助手语气`

语气只改变表达，不改变任务状态、排程规则或风险判断。

## 离线自动测试

当前离线回归覆盖课程导入与避让、主动推送、每日幂等、事务偏好、待安排池、
风险提醒、任务拆分、进度反馈、动态重排、稳定计划基线、晚间完成率和执行提醒，
共 58 项测试。`test_deepseek.py` 不属于离线回归，不在该测试集合中运行。

可在项目根目录运行：

```powershell
python -m unittest test_course_service test_push_runner test_push_service test_execution_delivery test_preference_service test_pool_service test_risk_service test_subtask_service
```

当前服务采用本地长连接和后台线程。关闭本地进程、电脑关机或休眠后，机器人主动
能力会停止；GitHub 仓库本身只保存代码，不会持续运行机器人。
